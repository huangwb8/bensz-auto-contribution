# BAC 版本差异视图优化

## 通俗解释：究竟发生了什么

账本只新增三条记录时，当前比较窗口仍把数千条历史在左右各展示一遍。用户需要自己寻找变化。改进后直接显示这三条新增记录，共同历史默认隐藏；需要追溯时仍可切换到完整时间线。

## 专业判断与目标

现有只读编辑器独立加载左右资源，缺少比较上下文。已有事件比较算法能识别新增、删除、修改与相对重排，可以复用。稳定版自定义比较标签没有公开左右资源。实际宿主检查表明，比较面板在同一组同时可见，因此仅关联该组恰好两个可见面板且满足内置 Git 的 `~`／工作区、HEAD／暂存区组合；其它情况保留原阅读器，不强制解释为 HEAD 比较。

## 改进方向与实施顺序

先核实稳定版标签 API 能否取得比较资源，再将版本关系传给只读查看器。比较模式复用事件内容比较，左右只展示各自涉及的变化，显示变化数量及相同历史隐藏提示；完整时间线继续作为显式入口。已识别比较采用各侧真实路径和版本，支持重命名；单侧新增／删除、任意历史版本无法明确关联时保留原阅读器。

验证和关联文件导航继续绑定各侧完整快照，隐藏记录只改变展示。另一侧无法读取时应报错，不能错误显示为“全部新增”。不改变 BAC 格式、身份声明与验证含义，不执行账本内容或引入提议版 API。

## 如何确认完成

真实点击源代码管理的暂存与未暂存条目，确认默认只显示变更、来源筛选统计仅含变更、无变化侧有明确提示，且完整时间线可恢复。覆盖新增、删除、重命名、内容修改、顺序变化、状态刷新和逐侧验证，保留明暗主题及窄窗口 JPG 截图。运行插件已有单元测试与实际扩展宿主检查。
