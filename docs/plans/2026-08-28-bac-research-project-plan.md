# BAC 严肃人机协作贡献溯源研究计划

> 协议状态：预注册草案（结构重构版）。本计划把“贡献边界恢复”设为唯一主要问题，把安全、机制、成本、隐私、领域复制和反馈复盘保留为次要或探索性问题。所有结论均以实际任务、样本、证据条件和披露粒度为边界。

## 研究定位

Bensz Auto Contribution（BAC）是一种面向人类—AI 协作的、可验证的贡献事件记录与审计视图。研究对象不是 AI 生成比例检测器，也不是作者认定、版权裁决或法律责任判断工具。

本研究只围绕一个核心判断展开：在底层事实相同的情况下，结构化的 BAC 事件记录是否比 Git 及其常规日志更能帮助独立审计者恢复“谁提出了什么、谁生成或修改了什么、工具观察到了什么、谁审阅并批准了什么”。

BAC 的安全主张限定为 tamper-evident：追加式事件、前序摘要、哈希链、签名和时间戳能够提高篡改可发现性，但不能证明初始写入真实，也不能阻止拥有写权限的人伪造或重写账本。

研究采用同一隐藏真值包程序化生成不同证据视图，避免把底层信息差异误当作 BAC 的事件本体效应。研究报告总体效应、三个预先选择领域内的分层效应及其不确定性，不把局部阳性结果外推为所有行业普遍适用。

除模拟任务外，本研究增加一个严格受限的生产环境观察层：在用户授权的真实项目中只读观察 BAC 的持续运行、记录覆盖、证据完整性、成本和审计可用性，并从真实工作片段中开展嵌套的盲法回放。生产观察用于检验生态可行性和初步优势信号，不把已有 BAC 账本直接当作真值，也不以单一用户的项目集合推断普遍效果。

## 研究问题

### 主要问题

**P1：贡献边界恢复。**

在软件工程、科研分析和临床病例讨论模拟任务中，BAC 相对于 Git+普通日志，是否提高独立审计者对关键贡献事件及其关系的恢复准确性？

主要终点为**任务级关键事件召回率（task-level macro recall）**。关键事件包括：

- 人类目标或约束；
- 方案选择、否决或关键决策；
- AI 生成或建议；
- 工具观察（命令、测试、差异或错误）；
- 文件实际修改；
- 测试结果；
- 最终人工审阅或批准。

只有事件节点及其必要关系均正确时，才计为该事件被召回。

主要比较预先固定为 `BAC − Git+普通日志`。`BAC − Git` 和不同 BAC 视图的比较属于支持性分析，不改变主要问题。

### 次要问题（保留，但降低推断权重）

**S1：机制与组件。** 去掉人类输入 provenance、语义校验或哈希链后，BAC 的收益是否下降；收益主要来自信息组织、语义约束还是完整性线索？

**S2：篡改可发现性。** 在已写入账本被删除、重排、复制、修改或来源漂白时，验证器和审计者能否发现异常，并保持可接受的误报率？该问题不检验初始写入真实性。

**S3：成本与隐私边界。** 记录 CPU/墙钟时间、账本体积、额外操作和中断的代价是多少；完整 prompt、低敏摘要和仅 hash 三种披露粒度的效用—隐私折中如何？

**S4：领域内可复用性。** 核心事件本体在三个被测试领域中能否保持可编码、可理解和责任边界可恢复；领域差异作为分层结果报告，不包装为跨行业普遍性证明。

**S5：反馈复盘（探索性）。** 自动记录的人类输入与 BAC 事件视图，是否改善下一轮反馈的可执行性、失败定位和错误避免？只有主实验完成并且资源允许时开展，不影响 P1 的确认性结论。

**S6：生产环境可行性与初步效用。** BAC 在真实项目的自然工作流中能否稳定记录多来源事件、保留可用证据并支持贡献边界回放；在独立真值重建的真实工作片段中，BAC 相对于 Git+普通日志是否呈现与 P1 同方向的初步优势？S6 是外部效度和实施性证据，不替代 P1 的确认性推断。

### 问题层级与结论规则

P1 是唯一确认性主要问题，只有 P1 达到预设最小实际重要差异（minimal practically important difference, MPID），且成本与隐私结果没有否定性信号时，才可声称 BAC 在本任务范围内具有实际审计收益。

S1–S4 是预先登记的次要问题，采用层级检验或 Benjamini–Hochberg 校正，并报告效应量、95% CI 和实际意义；S5 只作探索性报告；S6 先报告全量生产盘点和缺失模式，再报告嵌套回放的估计与不确定性。任何次要结果都不能替代 P1，也不能被改写成“BAC 全面优于现有工具”。

## 重要定义

### 贡献边界恢复

审计者根据给定证据，正确识别事件的直接来源、发生顺序、对象、证据和必要关系。它不是把一项成果分成若干百分比，也不是从最终代码外观推断作者。

### 真值包

与待测审计视图隔离保存的事件标注底座，包含证据位置、事件节点、关系和置信度：

- **直接观察事实**：命令及返回、文件 diff、测试输出、签名时间戳和文件 hash；
- **明确声明**：参与者明确写出的目标、约束、选择、否决和批准理由；
- **推断事件**：编码员根据多源材料推断的影响或责任关系。

P1 只使用前两层；推断事件仅用于探索性分析，不能被包装为客观事实。真值包不得由 BAC 视图反向生成。

### 事件、关系与来源

每条事件至少包括 `event_id`、`event_type`、`source_class`、`trust_level`、时间、前序摘要、对象、证据引用和验证状态。事件关系描述“提出—生成—观察—修改—审阅—批准”等依赖，不以批准事件覆盖创作来源。

来源严格区分：

- `human`：需求、约束、手写修改、审阅、批准和授权；
- `ai`：方案、代码、重构、修复或测试建议；
- `tool`：命令输出、测试、格式化、diff 和验证证据；
- `system`：genesis、checkpoint、verification 等账本自身事件。

声明事件与观察事件分开编码；未经核验的声明不能替代工具观察。

### 证据条件

从同一真值包和相同时间窗口生成以下视图：

- **B：Git**：commit、作者、时间、父提交和 diff；
- **C：Git+普通日志**：B 加命令、CI、IDE 和聊天摘要等已有记录；
- **E：BAC**：完整事件、来源、关系、证据和验证状态；
- **F：BAC 消融**：在统一最小 BAC 视图上分别去掉人类输入 provenance、语义校验或哈希链。

最终产物/最终 diff 和内容检测器/水印只作描述性补充基线，不参与 P1 的“全面优于”推断。证据视图生成器必须记录字段清单、事件数、字节数、输入 hash 和生成日志。

### 篡改可发现性、MPID 与领域复制

- **tamper-evident**：篡改更容易被验证器或审计者发现，不等于不可修改；
- **MPID**：正式研究开始前冻结的、对审计任务具有实际意义的最小差异；
- **领域复制**：在三个预先选定领域中重复同一核心事件定义并分层估计，不等于证明领域无关性；
- **审计成本**：阅读时间、记录开销、写入失败率、额外操作、账本体积和中断次数的组合，而不是单一 CPU 指标。
- **生产项目/工作片段**：在授权目录中自然发生并由真实参与者完成的项目或连续协作窗口；工作片段边界按预先登记的会话事件和时间间隔规则确定，不按结果好坏挑选。
- **生产观察证据**：来自真实部署的运行和记录统计，主要支持可行性、覆盖率、缺失机制和成本判断；没有独立真值时，不直接支持因果疗效结论。
- **独立真值重建**：由 BAC 之外的原始材料（版本历史、命令/CI 输出、文件差异、人工确认等）和盲法编码员建立的事件包；若某一事实只能从 BAC 得到，则标记为不可用于该片段的确认性评分。
- **外部效度信号**：生产观察与 P1 方向一致的结果，只能说明在被观察项目集合中具有可重复迹象；它不等价于随机化证据。

## 实验方案

### 总体设计原则

实验分为一个主实验和五类支持性研究（生产观察、组件机制、篡改可发现性、成本/隐私、领域复制/反馈复盘）。所有阶段共享同一任务验收标准、隐藏真值包和视图生成器；评分者不知道证据条件和真值。参与者不重复承担创作者和审计者角色。

领域固定为软件工程、科研分析和临床病例讨论模拟。临床部分只使用脱敏模拟病例，不提供或替代医疗建议。

### 主实验：贡献边界恢复（P1）

**为什么做。** 这是 BAC 最核心、最可证伪的效用主张，直接检验它是否帮助独立审计者解释人类与 AI 的协作过程。

**怎么做。** 每个领域设置跨文件实现/重构/故障修复/测试，或与之难度匹配的科研、病例讨论任务；每类任务设低、中、高三档难度。创作者完成任务并由采集器记录低敏人类输入摘要/hash、AI 计划与生成、工具命令及返回、文件 diff、手工编辑、审阅理由和最终批准。两名编码员依据冻结的编码手册建立真值包，Cohen κ 或 Krippendorff α 低于 0.80 时由第三名裁决并报告原始一致性和裁决比例。

审计者被随机分配到 B、C、E、F 四种条件之一，回答固定问题并提交结构化事件选择和简短解释。正式模型使用证据条件、领域及交互为固定效应，参与者和任务为随机截距；必要时加入预先登记的难度和经验协变量。

**预期可观察结果。** 结果可能表现为 BAC 在全部关键事件、仅高层决策事件、仅关系恢复上改善，或与 C 无差异。每种结果都按预先规则报告，不把局部改善扩写为全面优势。

**触发式调整。** pilot 若发现任务难度、视图信息量或条件间阅读时长明显失衡，先冻结问题定义不变，只调整任务配平、视图字段或培训；若可靠性低于 0.80，暂停正式招募并修订编码手册。正式数据锁定后不得根据结果新增比较对象或更换主要终点。

**样本。** pilot 至少每领域 8 名审计者（共 24 人），每人完成 6 个未见任务，不进入确认性分析。正式目标为 216 名审计者：三个领域 × 四种条件 × 每格 18 人，每人完成 6 个难度平衡任务。正式样本量以 pilot 数据进行分层模拟功效分析后冻结；若领域内精度不足，只报告总体效应和领域描述性结果。

### 组件机制实验（S1）

**为什么做。** 解释 P1 可能出现的效果来源，防止把 BAC 的收益笼统归因于“格式更复杂”。

**怎么做。** 使用统一最小 BAC 视图，分别移除人类输入 provenance、语义校验和哈希链；每个消融保持任务、底层事实和可见字段尽量匹配，至少每领域招募 24 名审计者，或依据 pilot 的领域×消融交互调整。

**预期解释。** 若移除某组件导致关键事件召回或关系恢复下降，可支持该组件的机制作用；若无差异，则收缩关于该组件必要性的叙述。

**触发式调整。** 若消融改变了可见事实总量而非仅改变组织方式，先重新生成视图并进行信息量审计；无法实现公平匹配时，该组件只作描述性结果。

### 对抗审计实验：篡改可发现性（S2）

**为什么做。** 单独验证 tamper-evident 边界，避免把完整性检测与贡献真实性混为一谈。

**怎么做。** 在干净账本、合法但复杂账本和脚本生成的攻击账本上测试：来源漂白、删除/重排/复制事件、修改 payload、删除证据及组合攻击；另设“初始写入即伪造”的边界案例。记录验证器通过/警告/拒绝、错误码、耗时，以及盲法审计子样本的攻击发现率、误报率、发现时间和 Brier 校准分数。

**预期解释。** 报告哪类攻击可被链完整性发现、哪类需要语义校验、哪些攻击会绕过验证器；不把验证通过表述为历史真实的证明。

**触发式调整。** 清洁账本误报率过高时先修复验证规则；攻击变换不能稳定复现时冻结攻击种子并降低攻击类型数量，不在看到结果后选择有利攻击。

### 成本与隐私实验（S3）

**为什么做。** 判断审计收益是否值得记录和披露代价，并寻找可部署的最低披露粒度。

**怎么做。** 比较完整 prompt、低敏摘要和仅 hash 三种输入记录粒度，测量敏感 token 暴露、人工可识别性、主要终点差值、CPU/墙钟时间、写入失败率、账本字节数、额外操作和中断次数，绘制效用—隐私前沿。

**预期解释。** 若低粒度摘要/hash 保持 P1 性能，可优先采用；若完整 prompt 才有收益，则明确其隐私成本，不把高披露误认为高质量方案。

**触发式调整。** 预设阈值为自动记录墙钟开销超过任务时长 5%、写入失败率超过 1%，或脱敏后 P1 下降超过 MPID。超过任一阈值时暂停高粒度扩展，转向摘要/hash 方案；阈值在 pilot 前可调整，正式研究后冻结。

### 领域内复制与反馈复盘（S4、S5）

领域效应和核心本体复用率作为 S4 分层结果报告：比较核心事件保留率、领域扩展字段比例、编码一致性、理解时间和责任问题准确率。若任一领域必须重写大部分本体或一致性低于 0.80，报告结构性缺口，不删除该领域结果。

反馈复盘 S5 采用个人或团队为随机化单位的平行 2×2 设计：输入记录（关闭/自动 `bac input record`）× 复盘界面（聊天/Git/BAC 事件视图）。只有 P1 数据锁定、质量门槛达标且资源允许时启动；比较反馈可执行性、失败定位、下一轮错误避免率、责任边界清晰度、阅读时间和中断次数。该实验不与 P1 合并分析。

### 生产环境观察与嵌套回放（S6）

**为什么做。** 模拟任务能够控制真值和随机化，但无法回答 BAC 在持续、混杂、会话边界不整齐的真实项目中是否真的可用。生产层用于补足生态效度，观察记录器面对长短不一的任务、脏工作区、缺失 Git 上下文和不稳定人工批准时的实际表现。该层安排在模拟主实验及支持性实验完成后，作为最后的外部效度检验。

**现有生产盘点（可行性快照）。** 2026-08-29 在用户明确授权的五个只读目录中，排除明显的 `tmp`、`.bensz-api` 和 `.git` 中间产物后，发现 24 个 `.bac` 账本，累计 6,361 条事件、容器文件约 5.69 MB。单账本事件数为 2–3,607 条，中位数 79；记录跨度约 0.014–88.8 天，中位数约 2.03 天。24 个账本均有连续事件序号且至少含一条 evidence，22 个同时出现 human/ai/tool/system 四类来源；只有 5 个包含 `human_approval`，20 个 manifest 显示工作区 dirty，2 个缺少 Git commit 绑定。该快照包含少量历史/legacy 账本，正式分析时按 canonical、历史和项目类型分层；由于生产账本仍会增长，实施前必须重新生成同口径快照。

使用当前版本验证器对这 24 个账本做只读复核后，6 个为 `pass`、15 个为 `warn`、3 个为 `fail`，共记录 443 条 warning。warning 主要是 `actor.declared_kind` 与 `source_type` 不一致；fail 例涉及 checkpoint 来源语义不符和账本内 `project.root_hash` 变化。这里的 fail 不是自动等同于恶意篡改，必须由版本迁移、项目重绑定、记录器缺陷和真实完整性破坏四类原因进行人工复核；外部生产目录不得为了“变成 pass”而执行 repair。

上述数字只证明真实运行已产生可分析材料，也提供了 BAC 具备发现语义冲突和上下文变化的初步信号，不是 BAC 优于 Git 的疗效证据。由于这些账本来自同一使用者及其项目生态，还存在选择偏差、操作者效应和项目间非独立性。它们同时暴露四个必须进入研究的真实问题：批准事件不能假定存在；dirty 或缺失 Git 上下文是常态而非异常；事件量和观察跨度高度偏斜，不能用简单项目平均数掩盖长账本的影响；验证器 warning/fail 可能同时包含产品缺陷、历史兼容性和真正异常。

**第一层：全量只读自然观察。** 对所有符合纳入条件的生产账本生成去标识化统计：事件数和增长曲线、四类来源覆盖、关键事件覆盖、evidence 链接率、验证/警告/失败及错误类别、checkpoint 和 approval 出现率、会话跨度、写入失败或中断、账本体积、工作区 dirty 与 Git 绑定缺失。每个 warning/fail 由独立复核表标记为记录器/版本迁移问题、项目上下文变化、可解释缺失或未解释异常；不得把不同原因合并成单一“失败率”。按项目类型（软件、pipeline/内容、科研/基金/论文、R）和账本规模分层，保留零事件缺失和低覆盖项目，不事后删除“表现不好”的项目。外部目录严格只读，不复制原始 `.bac`、完整 prompt、密钥或无关路径；只在当前研究工作区保存聚合统计和脱敏项目编号。

**第二层：真实工作片段的嵌套盲法回放。** 从生产账本按项目类型、事件规模（小/中/大）、是否存在 approval、是否 dirty 和时间跨度分层抽取工作片段，目标至少 24 个独立片段；若可用片段不足则全部纳入并只作估计和置信区间，不声称确认性效果。片段边界按预注册的 `session_started`、人类输入、checkpoint 及连续无事件时间间隔确定，不能按结果好坏挑选。

由不参与 BAC 视图生成的两名编码员，仅使用 BAC 之外仍可取得的版本历史、命令/CI 输出、文件差异、参与者明确确认和其他原始材料建立独立真值包；只能从 BAC 得到的事实标记为缺失，不计入确认性评分。随后从同一可用事实生成 Git、Git+普通日志和 BAC 回放视图，审计者随机看到一种视图，回答与 P1 相同的问题。视图顺序、审计者、片段和项目均记录，以混合模型处理重复观测；审计者与编码员不得看到另一条件或原始 BAC 全文。

**预期解释。** 全量观察若显示长期运行、来源覆盖和 evidence 记录稳定，支持 BAC 的部署可行性；若只有少数项目具备 approval 或 Git 完整绑定，则把“批准漏记”和“上下文缺失”作为实施性缺陷报告。嵌套回放若 BAC 相对 Git+普通日志方向一致，可作为 P1 的外部效度支持；若方向不一致或优势只在高事件量项目出现，则收缩适用范围并报告规模交互。

**触发式调整。** 生产账本若无法从 BAC 之外重建足够真值，不得用 BAC 自身补齐，只保留自然观察结果。若项目选择偏差明显，使用全量队列描述、分层权重和敏感性分析，不伪造随机化。若真实片段中 human provenance、approval 或 Git 绑定缺失率超过预设阈值，追加一次“缺失机制”分析；不因此修改 P1 主要终点。任何生产观察结果都不得反向改变已冻结的模拟任务、比较对象或样本量。

## 实验计划

### 阶段 A：方案与合规冻结

完成伦理、隐私和数据使用审批；冻结研究问题层级、MPID、任务验收标准、编码手册、攻击矩阵、主要终点、样本量模拟方案、排除规则和分析代码接口。明确公开数据中不包含完整私有 prompt、密钥和无关个人数据。

### 阶段 B：生产环境只读盘点

在五个已授权生产目录中扫描 `.bac` 文件名和容器元数据，排除 `tmp`、`.bensz-api`、`.git` 等明显中间产物；不写入、不移动、不覆盖任何外部文件。先输出项目类型、账本规模、事件跨度、来源覆盖、evidence、approval、验证状态、Git 绑定和 dirty 状态的聚合表，再冻结生产观察队列和排除理由。

本阶段只是实施前的只读盘点，不构成 S6 的正式生产观察或嵌套回放；正式 S6 按阶段 F 计划在模拟与支持性实验完成后最后执行。

本阶段的盘点结果只作为可行性先验和缺失机制基线，不能用于宣称 BAC 优于 Git，也不能据此事后改变 P1 的任务、比较对象、主要终点或样本量。

### 阶段 C：采集器、视图生成器与验证器

实现并测试事件采集、真值包隔离、B/C/E/F 视图生成、输入 hash、攻击脚本和验证器。运行 canonicalization、容器、哈希链、来源语义、脱敏、checkpoint、anchor receipt 和 CLI 端到端测试。记录每次生成的字段、字节数、事件数和版本。

### 阶段 D：编码试标与 pilot

先对各领域任务进行难度标定，再由两名编码员独立试标。完成 pilot（每领域至少 8 名审计者、每人 6 个任务），估计主要终点方差、阅读时间、条件间信息量差异、领域差异和排除率，运行分层模拟功效分析。

若 α/κ < 0.80、视图信息量不平衡、条件阅读时长严重不匹配或记录成本超过阈值，暂停正式招募，按预先允许的范围修订手册、任务配平或披露粒度，并保留修订记录。pilot 不进入确认性分析。

### 阶段 E：正式数据锁定与主实验

冻结任务、视图生成器、分析代码和随机化方案；随机化正式审计者，按领域、条件和经验分层，每人完成 6 个任务。先完成 P1 主实验，保存结构化答案、解释、阅读时长、设备信息和全部排除/缺失记录。

### 阶段 F：支持性实验与生产嵌套回放

在 P1 主实验完成后，依次运行 S1 组件消融、S2 对抗审计和 S3 成本/隐私实验；S4 领域复制结果从主实验和编码资料中独立整理；S5 反馈复盘仅在资源和质量门槛允许时作为探索性扩展启动。待上述模拟与支持性实验完成后，最后按项目类型、事件规模、approval、dirty、Git 绑定和时间跨度分层抽取真实工作片段，完成 S6 的独立真值重建和盲法回放。

生产嵌套回放必须使用 BAC 之外的原始材料建立真值，无法独立确认的事实记为缺失；不得用 BAC 自身补齐真值。任何支持性实验不得回写或改变 P1 的主要终点。

### 阶段 G：统计分析与稳健性检查

主模型报告总体 BAC−C 差值、各领域差值、领域交互、95% CI、双侧 p 值和标准化效应量，并判断 CI 是否跨越 MPID。提供完整案例、加权和敏感性分析；次要终点按预注册层级检验或 BH 校正。独立分析者使用冻结数据一次性运行主脚本并复现主表、校准图、成本/隐私图和攻击结果。

S6 的全量生产观察报告项目/片段级分布、缺失机制、来源和 evidence 覆盖、验证失败、approval 稀疏、dirty/Git 缺失、记录成本及其 95% CI 或 bootstrap 区间；嵌套回放报告 BAC−Git+普通日志 的方向、分层效应和片段内相关性。生产结果与模拟结果并列但分开推断：一致时作为外部效度支持，不一致时优先报告情境依赖和实施性缺口。

### 阶段 H：结论与公开材料

按结果触发规则收缩或支持论断：

- P1 超过 MPID 且成本/隐私可接受：声称在本任务范围内具有实际审计收益；
- 只改善高层决策或关系恢复：结论限定到相应事件层；
- 只改善攻击发现：结论限定为增强 tamper-evident 审计；
- P1 未超过 MPID：报告无差异、失败案例和不确定性，停止“全面优于”的叙事；
- 记录成本超过阈值：停止高粒度记录扩展，优先报告摘要/hash 方案。

发布去标识化 schema、视图生成器、攻击脚本、评分 rubric、分析代码和研究协议；原始私密材料仅保留受控访问版本。

## 小结

本计划以“BAC 是否改善人类—AI 贡献边界恢复”为唯一主线。Git 与 Git+普通日志是现有信息条件基线，BAC 及其消融用于检验结构化事件记录和组件机制；生产环境观察与嵌套回放补足真实部署证据；篡改检测、领域复制、成本隐私和反馈复盘均保留，但被明确放在次要或探索性层级。

执行上先冻结定义和真值包，完成生产目录只读盘点，再完成视图与验证器、编码试标和 pilot，随后锁定正式数据并完成 P1，接着开展 S1–S5 模拟与支持性实验，最后开展真实工作片段回放。所有分支都有预先规定的调整与停止规则，避免看到结果后扩展问题、增加比较对象或改变主要终点。

研究的最终价值不在于证明 BAC 在所有场景都更好，而在于用模拟主实验和真实生产观察共同回答：当 Git 和常规日志已经提供底层事实时，BAC 的事件、来源、关系和验证状态是否为贡献审计带来独立且值得付出的收益，以及这种收益能否在自然工作流中稳定出现。
