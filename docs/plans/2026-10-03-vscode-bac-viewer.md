# VS Code BAC 查看器实施计划

## 通俗解释：究竟发生了什么

现在点击 `.bac` 往往只能看到二进制文件提示，Git 也只能告诉用户整个文件变了。查看器相当于把账本翻开：用户能读到每条贡献记录，并看清本次提交新增了什么记录；点击关联文件还能查看真实代码差异。

## 专业判断：问题在哪里

BAC v2 使用 ZIP 容器，普通文本编辑器不能直接呈现。现有事件已经提供来源、时间、Git 上下文、文件路径与证据，适合做只读界面。文件 hash 和 diff 统计不包含完整代码，无法恢复所有未提交历史；插件必须明确比较所使用的 Git 版本。

## 要达到什么目标

- 点击 `.bac` 自动打开时间线，可按来源和摘要筛选，展开查看证据与原始事件。
- 对比 HEAD、暂存区与工作区账本，显示新增、删除、修改、顺序变化和项目绑定变化。
- 打开关联文件与 VS Code 原生代码差异；工作区差异与记录时提交差异分别标明。
- 完整验证复用 `bac verify --json`，没有工具时仍可查看，验证状态保持“未验证”。
- 打包 VSIX 并安装到本机 VS Code。

## 改进方向

### 用只读编辑器呈现贡献账本

采用 TypeScript 与 VS Code Webview，使用 VS Code 主题颜色与字体。界面以四类来源标记组成时间线，左侧浏览记录，右侧读详情。只读取数据，不运行事件内保存的命令，不修改账本。

### 让 Git 比较显示有意义的变化

从 Git 读取真实账本版本，用事件 ID 与实际内容比较，而不是信任记录自报的 hash。给出具体变化列表和可读的 JSON diff；文件代码 diff 使用明确的 HEAD、暂存区、工作区或记录时提交作为基线。

## 实施范围与顺序

1. 固定插件唯一源码目录，建立可构建、打包的扩展。
2. 实现容器读取、时间线、详情与验证工具入口。
3. 接入 Git 账本比较与代码 diff，补充错误和缺少历史时的提示。
4. 测试容器边界、比较正确性、路径访问与 VS Code 实际运行，保存界面截图并安装。

## 如何确认完成

- 项目账本在扩展宿主中能打开，筛选和详情可用，Git 比较能展示已有未提交事件。
- 不把可读取或 hash 声明当成验证通过；验证报告与实际读取的同一份账本绑定。
- 测试包括畸形 ZIP、重复条目、大小限制、同 hash 内容修改、删除、重排、路径越界与符号链接。
- TypeScript 编译、插件测试、现有 Python 测试和 VSIX 打包通过；本机扩展列表包含插件。

## 风险与边界

只支持桌面版 VS Code 和其远程 Node 扩展宿主；完整验证需要运行环境中安装 BAC CLI。外部程序仅在可信工作区运行。ZIP 解压有大小与成员数量限制；Webview 禁止外部资源，并使用纯文本呈现账本内容。签名与锚定能力以原有验证器报告为准。

### 审查修正

- **Important：验证与文件的绑定。** 并发替换可能让验证器读到其它版本；已改为验证私有临时快照，并核对当前文件摘要、事件数和 head，文件更新使验证失效。界面测试验证通过。
- **Important：暂存版本的文件上下文。** 相同事件 ID 在工作区与暂存区可能有不同内容；文件操作现绑定到所选变化的实际事件，避免误用工作区记录的提交信息。
- **Minor：记录者显示与代码语法识别。** 已读取 BAC 的 `actor.declared_name`，虚拟代码文件保留真实文件扩展名；实际界面与原生 diff 已检查。
- 审查后没有待处理的已知问题；签名、代码历史恢复和支持格式的边界已写入插件说明。
