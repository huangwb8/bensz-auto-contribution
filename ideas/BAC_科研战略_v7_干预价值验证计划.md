# BAC 科研战略 v7：验证人类干预的实际价值

> 日期：2026-09-08
>
> 定位：科研方向与分阶段执行计划，不是实验结果或发表承诺。
>
> 主线：在编程验证盲区中，测量真实人类审阅消息对结果的条件效应，并检验这种测量是否可信。
>
> 路径：按用户要求保存在项目根目录的 `ideas/`。保留 v6 和既有计划，不静默覆盖或废止其他研究路线。

## 结论与执行原则

**BAC 值得继续做，但第一篇不应以“人类贡献仍然很大”为预定结论。** 应允许人类干预有益、无效、有害，或可被自动审阅替代；测不准时，也必须允许结论是“不确定”。

第一阶段只回答一个主要问题：

> 在现有测试漏检的编程任务中，相对不提供审阅意见，交付一条真实人类保障性干预，是否改善独立验收结果？

同时开展有限的测量效度检查，并以额外 AI 审阅作为重要次级对照。资源配置策略、自主度与贡献集中度、跨领域推广均后置。

第一篇的最小成果应是：一个边界明确的实验问题、一套可恢复的对照协议、一组带不确定性的结果。工具、标签和可视化只服务于这些成果。

## 从 v6 到 v7 的调整

| v6 的安排 | v7 的决定 | 原因 |
| --- | --- | --- |
| 稀疏高杠杆是核心假说 | 降为后续探索性问题 | 减少确认动作本身就可能提高剩余动作平均值 |
| 先建立贡献体系，第二篇再做因果验证 | 第一篇即做少量可控分支验证 | 先证明测量有用，再扩大覆盖 |
| Production／Direction／Assurance 作为贡献向量 | 保留为可重叠的行为标签 | 分类、影响范围和结果效应不是同一个量 |
| leverage 包含 Outcome delta，又用于解释结果 | 预测分数与事后效应严格分离 | 避免把答案放进指标后自证 |
| 以 LOC 接近作为匹配目标 | 在分组前固定任务、信息和预算 | 不按干预后的 LOC 筛选样本 |
| 8–10 个任务、24–30 条轨迹 | 8–10 个任务仅用于可行性 pilot | 多臂重复重放需要更多运行，且运行数不等于独立样本数 |
| 先统一多平台事件图与适配器 | 先一个 harness、一个模型、一类审阅流程 | 将资源用于恢复能力与独立结果验证 |

## 研究定位与相关工作

当前定位是**人类保障性干预的条件效应、测量效度与自动审阅替代边界**，不是首次研究人类贡献，也不是首次提出反事实重放。

| 直接相关工作 | 已有覆盖 | v7 如何使用，而不重复宣称 |
| --- | --- | --- |
| CentaurEval [R1] | 编程中的人机协作价值及不同介入条件 | 作为协作对照设计的直接先行工作；BAC 收窄到保存状态处的真实审阅消息与独立验收 |
| Causal Agent Replay [R2] | 步骤干预后向前执行，研究失败归因 | 借鉴干预契约与恢复要求，不宣称重放思想首次 |
| Coding process evaluation／SCAE [R3] | 已区分行动、任务和步骤级测量，并报告有限预算下的效应估计困难 | 把可测性与精度设为前置门槛；仅迁移到 coding 不算创新 |
| 信息贡献研究 [R4] | 用概率而非字面复制率刻画贡献，也包含多轮纠错 | 不将其弱化为 LOC 式基线；明确本研究测的是独立结果变化 |
| 样本量依据 [R5] | 讨论精度、功效、最小有意义效应与资源约束等样本量理由 | pilot 用于估计可行性，正式样本依据预先选择的目标设计 |

R1 的作者记录注明 ICML 2026 接收，R4 为 ACL 正式论文，R5 为正式期刊论文；R2、R3 在本计划中按预印本参考，不视为成熟共识。以下具体实验安排是针对 BAC 提出的方案，不是这些论文共同推荐的标准协议。

前轮已有其他相关工作核查，但本版只保留直接改变实验设计的参考。未完成穷尽式查新；在正式实验冻结前，还要定向检查真实人类监督、主动求助和编码干预测量是否已有等价协议。

## 科学问题与可证伪假设

### RQ1：人类保障性干预是否改善结果

在预先定义的验证盲区任务集合中，比较人类审阅消息 H 与无额外审阅消息 C 的独立验收成功率。这是唯一确认性主要对比。

**假设 H1**：在目标任务集合中，H 相对 C 的平均增益达到事先定义的最小有意义效应。若精确区间排除了该幅度，则该强度的假设被削弱或否定；若区间很宽，则判为证据不足，而不是“没有贡献”。

错误类型间的差异是预先定义的次级分析，不根据看到的结果重新挑选“人类最擅长”的任务作为主要分析。

### RQ2：过程评分是否测到了结果效应

比较只使用干预前状态与拟交付消息的评分，能否在未参与训练的任务上，比消息长度、确认次数、行为标签或简单风险规则更好地区分可观测效果。

**假设 H2**：经独立数据校准的评分，在预注册的任务级检验中有实际增量。如果简单基线已经同样有效，或优势在新仓库消失，就不继续扩建复杂指标体系。

此问题是第一篇的次级方法学研究。只有训练样本与独立验证样本足够时才学习新评分器；pilot 阶段先检验少量冻结规则，不用小样本训练黑箱后报告漂亮相关性。

### RQ3：额外 AI 审阅能否替代人类意见

比较 H 与额外 AI 审阅消息 A，在同等公开信息和预定资源条件下的质量、成本与损害。

**假设 H3**：干预来源的相对效果依赖任务类型与资源，不由“human”或“ai”身份字段决定。H−A 默认作为次级估计；不能以“不显著”宣布两者等效。

若要正式声称“可替代”，应在确认性实验前独立规定非劣效界值、成本要求和相应样本量。资源不足时，只报告区间与待确认的替代边界。

## 测量对象与边界

### 区分来源、角色、影响和效果

| 层次 | 回答的问题 | 本版规则 |
| --- | --- | --- |
| 来源 | 这条事实来自哪里 | 保留 human、ai、tool、system；不得把模拟人类登记成真实人类 |
| 角色 | 行为在做什么 | Production、Direction、Assurance 可多标签；角色不是功劳份额 |
| 影响 | 改了多少、波及哪里 | 消息、修改范围、执行路径等是描述量，不能默认正向 |
| 效果 | 相对明确对照，结果怎样变化 | 报告差值、区间、成本与损害；允许正、零、负和不确定 |

保障性干预在本研究中指：指出潜在错误、澄清任务已有的语义约束、提出可检验的反例或验证建议。主要流程不允许审阅者直接改代码；否则测量对象会混入实现劳动。

审阅者可以建议新的检查，但**不能事后修改主要终点、隐藏测试或验收标准**。新增测试可作为反馈交给执行 Agent，独立评价始终由冻结规则完成。

### 估计的是消息交付效应，不是人的全部价值

对检查点状态 \(s\)，固定执行 Agent 的后续策略 \(\pi\) 和资源预算 \(b\)，定义：

\[
\Delta_{H,C}(s)=
\mathbb{E}[Y\mid s,\operatorname{deliver}(h_s),\pi,b]
-\mathbb{E}[Y\mid s,\operatorname{deliver}(\varnothing),\pi,b].
\]

\(Y\) 为独立验收是否成功，\(h_s\) 是分支运行前已经收集并冻结的一条真实审阅意见。期望针对后续执行随机性；正式主要结果是目标任务分布上的平均差值，而不是每个事件都能被精确归因。

这是给定状态、消息生成过程和替代方案下的效应。它不是该审阅者的全部贡献，也不是完整人机协作政策的效果。多个干预可能相互依赖，本版不把单步差值相加为“人类贡献 100%”。

## 实验范围与任务准备

### 第一阶段只使用受控编程环境

- 一个执行模型的固定版本、一个 harness、固定工具集合和封闭测试环境。
- 首先研究函数边界、跨模块一致性、状态恢复等可独立验证的语义缺陷；不同时扩展为开放科研或真实生产部署。
- 采用可公开或已获明确使用授权的代码与任务，不默认接入生产仓库、客户数据或真实外部副作用。
- 将原生缺陷任务与人工植入缺陷分层记录，分别报告；不能把人工设计挑战集的效应当作生产环境平均收益。

### 挑战集与无缺陷对照

挑战集 D：执行 Agent 产出候选后，当前公开测试通过，但独立冻结验收尚有失败。无缺陷对照 K：公开与独立验收均通过，用于观察过度纠错和审阅引入回归。

任务策划者可以依据隐藏验收构造 D/K，但审阅者与执行 Agent 均不知道分类和答案。主要估计预先限定在 D；K 是独立安全对照，不通过任意混合比例制造总体增益。

检查点选择规则在观察审阅效果之前固定，例如“首次公开测试通过的候选状态”。无合格检查点、准备失败和基线无法运行的任务均进入筛选流图；不得只保留后来被人类成功救援的任务。

禁止按分支结束后的 LOC、成功率或改动是否漂亮筛选样本。若因基础设施故障必须排除，适用预先定义、与研究结果无关的规则。

## 对照实验协议

### 核心分支

| 分支 | 给执行 Agent 的额外输入 | 作用 |
| --- | --- | --- |
| C：继续执行 | 不交付额外审阅消息，按统一恢复协议继续原任务 | 无新增审阅信息的主要对照 |
| H：人类审阅 | 交付一条已冻结的真实人类意见 | 主要干预 |
| A：AI 审阅 | 交付一条独立生成、已冻结的 AI 意见 | 自动审阅次级对照 |
| N：中性消息 | 通过相同消息通道交付预定义的无诊断内容消息 | 检查恢复提示、额外消息和形式确认本身的影响 |

pilot 的重复预算以 C/H/A 三臂为主；N 在预选子集上验证管线。若 N 与 C 差异不可忽略，正式设计需在收集确认性数据前加入完整 N 臂，或明确主要效应包含消息通道作用。

N 不一定天然“无效果”；它是需要检查的负对照，不是已知为零的真值。工程正对照可使用受控、已知会改变输出的消息，但必须标为人工构造，不能作为真实人类能力证据。

### 从同一状态分支，而不是从最终结果倒推

1. 冻结任务说明、独立验收、检查点规则和资源预算，分离策划者与审阅者的资料权限。
2. 生成候选状态，保存工作树、执行上下文、公开测试与工具状态；执行恢复自检。
3. 向人类和 AI 审阅者提供相同的公开证据包，分别取得意见；不得读取另一方意见或隐藏答案。
4. 冻结消息、标注来源并保存必要证据；人类允许提交“未发现问题”，此类意见也保留。
5. 随机化分支执行次序，在隔离副本上重复执行 C/H/A；不让缓存、文件或工具记忆跨分支泄漏。
6. 后续执行不再接受人工纠正，使用一致的停止规则与预算。模型采样种子仅在接口确实支持时记录和使用，不能声称 API 天然可确定重放。
7. 分支结束后，由与干预生成隔离的评价流程运行冻结验收，保留失败和资源耗尽结果。

H 和 A 的审阅消息在第一阶段各固定一条。因此主效应条件于已采集消息；不能仅靠多次执行重放估计“所有人类意见”或“所有 AI 审阅采样”的变异。后续扩展再增加多位审阅者及多份独立 AI 意见。

### 公平性不是把不同资源强行换算成同一个数

共同约束是相同任务说明、公开代码、日志和可查询证据，不允许任何一方接触隐藏测试答案。允许的静态分析或测试工具也须事先列明；第一阶段可先限制为同一静态证据包，减少信息获取差异。

人类时间、AI token、API 费用和执行预算分别报告。初始试运行可以用“人类审阅上限 10 分钟、AI 审阅上限 10,000 输出 token”作为可调整的资源情景，但这**不叫经济意义上的同预算**，也不是文献给出的最佳参数。

pilot 后结合实际延迟与成本冻结正式资源条件，并报告多个预定成本情景。执行 Agent 在 C/H/A 中拥有同样的后续调用和时间上限；额外审阅开销单独计入总成本，不能只记执行成本。

## 人类参与与信息隔离

pilot 可先邀请 3–5 名有相关开发经验的参与者，用于检查操作流程和意见可用性；这不是代表性样本或正式功效保证。记录去标识化经验分层，不按事后效果定义“专家”。

任务分配和顺序预先随机化或平衡；同一参与者原则上不重复审阅同一个任务的不同版本，以减少记忆泄漏。若多任务来自同一仓库，记录并分析熟悉度。

H 与 A 的输入来源在审计层保留；执行 Agent 默认接收统一格式、没有来源身份标签的消息，从而优先比较内容作用，而非“相信人类”标签的提示作用。身份提示效应不进入本篇主要设计。

在采集前完成适用的伦理审查判断、知情同意、退出和数据处理安排；本计划不代替相关机构要求。参与者身份和联系方式不进入 BAC；可识别原始资料不得写入普通任务工作区或版本库。

没有真实参与者时，可以先用 AI 消息测试工程管线，但必须标记为模拟数据，不能用来回答 RQ1 的人类干预问题。

## 评价指标与防泄漏规则

### 主要指标保持单一

主要终点：在规定执行预算内，冻结的独立验收是否全部通过。主要效应量：任务加权的 H−C 成功率差，报告区间；默认各合格任务等权，多个检查点不得无意中增加该任务权重。

次级指标包括：隐藏缺陷解决情况、公开测试回归、无缺陷任务损害率、人工审阅时间、执行与审阅成本、运行失败类型。避免将质量、时间和费用未经论证压成单一总分。

新增的测试用例数、代码行数、模型自报置信度和 LLM judge 评分都不是独立正确性真值。确需人工判读时，使用不知道来源与分支的评审者、冻结 rubric 和明确的不确定性记录；不把它替代可执行主要终点。

### 预测分数与效果参考分开生产

用于 RQ2 的评分只能读取检查点前的公开状态及拟交付消息。不得读取分支后代码、测试变化、最终成功标签或其他分支结果。

行为标签的标注者也不看最终结果；分别报告每个标签的一致性及歧义，而不是为追求整齐强迫标签互斥。标注分歧与仲裁规则写入 codebook。

评分权重、阈值和任何训练在开发集完成后冻结；确认性评价按任务或仓库隔离，不能把同一检查点的不同重放分到训练与测试两侧。

效果参考来自多次独立执行，有抽样误差，不称为无噪声“真值”。单事件重复次数不足时，不强制贴正、零、负标签；优先报告区间或在可估计的任务组层面检验。

## 统计分析与样本量

### 分清运行数与独立样本数

一次 rollout 是技术重复，不是一位新的审阅者或一个新的任务。正式分析保留任务、仓库、检查点、审阅者和执行重复层级，不把所有事件摊平做独立样本检验。

先在检查点内计算各臂成功率和配对差，再按冻结的任务权重汇总。正式模型或重采样方案应根据最终分配设计处理共享仓库与重复审阅者；存在交叉结构时，不使用忽略该结构的普通逐行 bootstrap。

pilot 聚类数量很少时，主要报告逐任务结果、运行稳定性和估计区间，不以脆弱的总体显著性作为继续依据。正式模型、稳健性方法与可识别范围在确认性数据生成前写入统计分析方案。

### 主要、次级与探索分析分开

- RQ1 的 H−C 是唯一主要对比，默认双侧 95% 区间并允许负效应。
- H−A、缺陷分型、来源交互和成本比较为次级；若需要确认性声明，预先规定比较族与多重比较处理。
- 不显著不代表等效，点估计为零不代表“零贡献”。
- autonomy、concentration、专家差异及稀疏高杠杆，仅在额外设计支持时开展探索，不混进主要成功标准。
- 若 pilot 后修改任务、评分或假设，pilot 保留为开发数据，不能悄悄合并成未受探索影响的确认性样本。

### pilot 的运行预算

建议从 8–10 个验证盲区任务、每任务 1 个检查点、C/H/A 各 5 次重放开始，共 **120–150 次后续执行**。另设 2–3 个无缺陷任务与一个小型 N 对照子集；它们的准备、审阅与重放成本额外计入。

通用预算关系为：任务数 × 每任务检查点数 × 分支数 × 每分支重复数；还需加上基线生成、审阅、环境准备和预注册的故障重试成本。这里的数字只服务可行性检查，不代表足够检测某个科学效应。

正式样本依据 R5 的原则，以最小有意义效应、目标精度或功效和可承受成本论证。进入正式招募前必须锁定：主要效应阈值、目标区间宽度、任务/参与者分配、重放次数及总预算上限。

可以先比较 5、10、15 个百分点的效应情景，结合 pilot 方差与保守情景进行模拟规划；这些是资源敏感性分析，不是实验后挑选最容易显著的假设。若可用预算达不到所需精度，就收缩为可行性或测量边界报告，不冒充确认性结果。

### 故障与缺失不能事后挑选

模型产生无效输出、预算耗尽、工具使用错误等属于系统在实验条件下的结果，按冻结规则计入主要分析。纯基础设施中断另设分类和重试上限；原始失败记录保留，不能无上限重跑到成功。

恢复失败若在随机化或分支分配后发生，也必须进入运行流图和缺失敏感性分析。若模型版本、工具行为或环境出现无法控制的漂移，暂停实验并定义新批次，不把不同条件无标记地混合。

## BAC 的工程范围与威胁模型

### 当前基础与缺口

现有 `src/bac/core/schema.py:13` 已区分四类来源；`src/bac/service/evidence.py:43` 记录文件存在性和摘要，`src/bac/service/evidence.py:66` 记录 diff 统计。它们是证据基础，不是完整工作树、模型上下文与工具状态快照。

本计划只提出后续工程任务，本轮不修改事件 schema。优先使用外置、版本化的实验清单与证据文件，通过 BAC 记录引用和摘要，不一开始升级协议或增加大量事件类型。

### 最小实验记录

| 记录 | 最低必要信息 | 边界 |
| --- | --- | --- |
| 任务与检查点 | task/checkpoint ID、仓库 revision、恢复材料索引、环境/模型版本 | hash 不等于内容可重建，恢复材料必须实际存在 |
| 审阅消息 | 匿名来源、消息摘要/获准公开内容的引用、采集时间、预算 | 不保存身份资料、私有提示或凭据 |
| 分支运行 | arm、父检查点、重复编号、执行次序、预算、开始/结束及失败类别 | 哈希链前序只表示账本顺序，依赖关系要另行明确 |
| 独立评价 | 验收版本、评价输出、exit code、预算与结果类别 | 隐藏测试与答案不进入审阅者可读上下文 |
| 分析输出 | 数据版本、排除规则、模型/参数、区间及敏感性结果 | 不能从相关性直接写成人类价值结论 |

源类型与角色正交：人类设计检查是 human；AI 生成修复是 ai；工具执行测试是 tool；账本检查点是 system。调用工具的人不会自动获得工具结果全部功劳，人工接受也不改写 AI 的生成来源。

### 主要失效方式与应对

- **分支污染**：工作树、缓存、环境和记忆独立；执行前检查相同起点，禁用非必要网络副作用。
- **评价泄漏**：隐藏测试与答案分离，日志权限检查，测试设计在干预前冻结。
- **追溯性造故事**：前置收集消息，保留无意见、失败与否决；不事后由 LLM 补写成真实观察。
- **日志完整性误判**：签名或哈希不证明内容真实性和采集完备；声明、观察和验证结果保持区分。
- **恢复不可识别**：无法恢复的私有上下文、模型漂移或外部状态必须披露，不能声称精确重放。
- **隐私泄露**：只采用公开或可合法授权的实验资料；对需受限保存的信息使用单独受控流程，BAC 和普通项目文件仅保留非敏感引用。

完整行为模型仍采用追加式事件；更正通过追加说明实现，不重写历史。涉及审计、摘要、身份与签名的未来代码变更必须另配测试。

## 分阶段执行与停止条件

表中的时间是具备基本执行环境后的工作量参考，不包括招募、伦理流程和外部服务等待；不是完成日期承诺。

| 阶段 | 输入与主要动作 | 交付物 | 继续条件 | 停止或转向条件 |
| --- | --- | --- | --- | --- |
| 范围冻结，约 2–3 个工作日 | 复核直接先行工作；选定一类任务；明确 RQ1、信息边界和预算 | 简短差异表、任务纳排与干预契约 | 有具体、可证伪的增量 | 仅剩换名称、换格式或已有等价协议 |
| 恢复与对照管线，约 5–10 个工作日 | 实现单一采集入口、隔离恢复、C/H/A/N和隐藏评价 | 2–3 个公开玩具任务、恢复检查及故障日志 | 能检查同起点，独立评价无泄漏，所有分支可追溯 | 无法隔离、无法恢复或依赖不可控外部状态 |
| 真实意见 pilot，约 5–10 个工作日 | 收集 8–10 个挑战任务与额外对照，取得真实意见，重复执行 | 可行性数据、成本分解、误差与缺失报告 | 人类流程可用，运行预算允许达到后续目标精度 | 只能用 AI 模拟人类，或估计噪声/成本使问题不可识别 |
| 预注册与样本锁定，约 2–4 个工作日 | 根据 pilot 和保守情景规划样本；冻结模型、终点与统计方案 | 正式实验协议、预算上限、停止规则 | 在资源内能回答主要问题 | 只能做低精度探索却仍试图作确认性声明 |
| 确认性实验 | 使用新的任务/审阅分配，按冻结协议采集 | 冻结数据、主要与次级估计、偏离记录 | 依据协议完成，不依据效果好坏决定是否继续采集 | 安全、授权、重大漂移或预算触发已定停止条件 |
| 复核与论文组织 | 复核证据链、误差、失败案例和外推边界 | 方法与结果草稿、可公开复现材料 | 结论强度与证据相符 | 发现重大泄漏或错误时先撤回相关分析，不补故事 |

在 pilot 前就写下工程预算上限与质量要求；pilot 可以修订正式实验设计，但不能删除不利的 pilot 记录。正式实验开始后不根据显著性随意扩样；确需序贯设计时必须提前定义。

## 第一篇论文的组织方式

暂定题目：**When Human Review Changes the Outcome: Measuring Assurance Interventions in Agentic Coding**。题目不预设人类必然有优势。

论文主体按问题、干预协议、恢复与证据保障、主要效果、测量效度、失败边界展开。至少准备以下图表：

- 任务筛选和运行流图，显示准备失败、缺失和预算耗尽。
- 实验分支与信息权限图，明确谁能看见什么。
- 逐任务 H−C 与 H−A 差值和区间，而不是只展示成功案例。
- 质量—人工时间—模型成本的分开展示，保留无缺陷任务损害。
- 过程评分与独立效果参考的校准图，显示不确定性和任务外验证。

正向效果、自动审阅可替代、指标失效和现有预算下不可识别，都可以是诚实结果。是否足以投稿取决于方法增量和证据质量，不保证负结果本身就构成论文。

## 后续路线与明确不做的事

只有第一篇证明测量可信，第二阶段才研究：在固定人工时间下，怎样选择介入点；再之后考虑自主度、稀疏高杠杆、多 Agent 和领域迁移。

如果无法取得真实人类数据或完成可信分支恢复，可转向“最小证据与贡献判断可识别性”，但它是独立替代题目，需重新查新和定义评价，不能用来掩饰 RQ1 未完成。

当前不建设通用 IDE、全平台 trace 适配器、万能贡献百分比、复杂 Shapley 评分或区块链创新叙事；不将版权、署名或责任裁定塞入第一篇；不以 LLM 阅读完整结果后给“人类 67%”作为测量终点。

BAC 的产品定位仍是 tamper-evident 的过程证据工具。科研层读取并检验证据，不反向把未经验证的科研假设写成工具事实。

## 启动前检查清单

- [ ] 主要问题只有一个；H−C、目标任务分布和最小有意义效应已明确。
- [ ] 确认性与探索性分析分开，未知样本量有明确的 pilot → 规划 → 冻结路径。
- [ ] 任务与检查点规则先于干预效果，挑战集和无缺陷对照不混淆。
- [ ] H/A 使用共同公开信息，资源以向量报告，不偷换“同预算”。
- [ ] 真实人类参与、权限与必要的伦理/数据安排已落实，模拟数据标记清楚。
- [ ] C/H/A/N 的含义、消息通道和后续策略已固定。
- [ ] 恢复能力、分支隔离、隐藏评价与故障处理通过预先检查。
- [ ] 过程分数看不到未来结果，训练与验证按任务/仓库隔离。
- [ ] 能报告无效、有害和不确定，而不是只寻找正向贡献。
- [ ] BAC 仅保存必要非敏感证据，保留四类来源与追加式更正。
